# 리뷰 규칙

PR 리뷰(Claude /code-review · 코드래빗)에서 반복해서 나온 지적을 규칙으로 모은 문서. 코드를 쓰기 전에 읽고, PR 올리기 전에 아래 체크리스트로 한 번 더 본다. 새로 나온 지적 중 다시 나올 만한 것은 여기에 덧붙인다.

## 스키마 · 엔티티

### 1. NOT NULL 칸을 추가하면 기존 데이터와 시드를 같이 본다
- 기존 행과 시드 SQL(`src/main/resources/db/seed-local.sql`)이 그 칸 없이 INSERT 해도 들어가는지 확인한다. 기본값이 있으면 `@ColumnDefault` 로 DB DEFAULT 를 둔다.
- 로컬 전용이라 운영 마이그레이션은 두지 않는다. 운영 DB 가 생기면 그때 마이그레이션 도구를 정한다.
- 나온 곳: #20 · #24 · #25 (#25 는 시드 SQL 이 실패해 로컬 서버가 안 떴음)

### 2. 상태값이 있는 엔티티는 다른 경로의 저장이 덮어쓰지 않게 한다
- 조회수 증가처럼 같은 행을 다른 목적으로 저장하는 경로가 있으면 `@DynamicUpdate` 로 바뀐 칸만 UPDATE 하거나 행을 잠근다.
- 나온 곳: #24 (상세 조회의 조회수 저장이 그사이 숨겨진 글을 다시 공개로 덮어씀)

### 3. 에러 코드 접두사가 다른 도메인과 겹치지 않는지 본다
- `docs/error-codes.md` 의 접두사 표를 먼저 확인한다 (예: R = Region, RP = Report).
- 나온 곳: #24

## 조회 · 응답

### 4. 공개 API 는 삭제 · 숨김 · 탈퇴 데이터가 섞여도 깨지지 않게 한다
- 숨김 · 임시 · 삭제 조건은 목록 · 검색 · 상세 · 내 목록에 모두 적용한다.
- 탈퇴한 회원 행이 섞여도 500 이 나지 않는지 본다.
- 나온 곳: #23 · #24 · #25

### 5. 목록 응답에 쓰는 연관은 한 번에 가져온다
- 응답 DTO 가 쓰는 연관(글쓴이 · 도시 · 카테고리 등)은 `JOIN FETCH` 나 `@EntityGraph` 로 가져와 N+1 을 막는다. 페이지 쿼리는 `countQuery` 를 따로 둔다.
- 나온 곳: #20 · #23

### 6. 정렬 파라미터는 고정하거나 허용 목록으로 받는다
- `Pageable` 의 sort 를 그대로 쿼리에 넘기지 않는다. 같은 값끼리 순서가 정해지도록 `id` 보조 정렬을 붙인다.
- 나온 곳: #23 (`sort=likeCount` 로 쿼리가 깨져 500)

## 동시성 · 무결성

### 7. '검사 후 저장'은 잠금이나 DB 제약으로 막는다
- 한도 · 중복 검사 뒤 저장하는 흐름은 동시 요청에 뚫린다.
- 개수 한도(장소당 사진 3장, 신고 3건이면 숨김 등)는 그 개수를 세는 기준 행을 잠가 검사와 저장을 직렬화한다. 예: 게시글 행 잠금(`findByIdWithLock`). 유니크 제약으로는 서로 다른 항목이 동시에 들어오는 것을 막지 못한다.
- 중복(한 사람당 한 번 등)은 유니크 제약으로 막는다.
- 유니크 제약에 걸리는 게 정상 흐름에서도 생길 수 있으면(동시 첫 가입 등) 실패한 트랜잭션이 끝난 뒤 새 트랜잭션에서 횟수를 정해 다시 시도한다.
- 나온 곳: #9 · #20 · #24 · #25

### 8. 중복 확인은 DB 유니크 제약과 같은 범위를 본다
- 소프트 삭제(`deletedAt`)된 행도 유니크 제약에는 걸리므로, 중복 확인 쿼리도 탈퇴 · 삭제 행까지 본다.
- 나온 곳: #25 (탈퇴 회원 닉네임으로 가입하면 500)

## 외부 연동

### 9. 외부 API 호출은 트랜잭션 밖에서, 시간 제한을 두고 한다
- HTTP 호출을 먼저 끝내고 DB 작업만 트랜잭션으로 묶는다. 연결 · 응답 시간 제한을 둔다.
- 브라우저가 이동하는 흐름(OAuth 콜백 등)은 어떤 실패든 500 대신 프론트로 돌려보낸다.
- 나온 곳: #25

## 문서 · 테스트

### 10. 바뀐 동작은 같은 PR 에서 문서도 고친다
- `api-design` · `business-rules` · `error-codes` · `entity-design` · `auth-policy` · Swagger 설명.
- 나온 곳: #20 · #22 · #23

### 11. 테스트는 핵심 스펙을 직접 확인한다
- 순서 · 경계값 · 한도는 결과를 직접 검사한다. 에러는 상태 코드와 함께 다른 원인과 구분되는지 본다(예: 본인 글 400 과 사유 누락 400).
- 동시성 수정은 예외를 가짜로 던지는 테스트만으로 끝내지 말고, 실제 DB 제약 위반을 거쳐 복구되는지도 확인한다.
- 나온 곳: #23 · #24 · #25
