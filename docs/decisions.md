# 설계 결정 사항

## 아키텍처 결정

| 항목 | 결정 | 이유 |
|------|------|------|
| 패키지 구조 | 도메인형 | 도메인 단위 응집도, GOTCHA 벤치마킹 |
| 공통코드 시스템 | CommonCode 테이블 | 상태값 유연한 관리 (ENUM은 고정값만) |
| soft delete | deleted_at 컬럼 | 데이터 보존, 복구 가능 |
| like_count 역정규화 | Post 테이블에 직접 저장 | 목록 조회 성능 (JOIN 제거) |
| 인증 | JWT (Access + Refresh) | Stateless, 확장성 |
| 캐시 | Caffeine (인메모리) | 지역/카테고리 등 마스터 데이터 |
| 파일 저장소 | AWS S3 | 확장성, 비용 효율 |
| DB | PostgreSQL (Supabase) | 무료 호스팅, GOTCHA와 동일 |

## 비즈니스 결정

| 항목 | 결정 | 비고 |
|------|------|------|
| 게시글 상태 | 공통코드 (DRAFT/PUBLISHED/HIDDEN) | 유연한 상태 관리 |
| 좋아요 | 토글 방식 | 한 엔드포인트로 추가/취소 |
| 회원 탈퇴 | Soft delete + 게시글 유지 | 커뮤니티 데이터 보존 |
| 이미지 | 게시글당 최대 10장 | S3 업로드 |

## 기존 프로젝트(2021)에서 변경된 점

| 항목 | 기존 | 현재 | 이유 |
|------|------|------|------|
| ORM | JDBC 직접 쿼리 | Spring Data JPA | 생산성, 유지보수성 |
| 인증 | 세션 + 평문 | JWT + BCrypt | 보안, Stateless |
| DB | Oracle | PostgreSQL | 무료, Supabase 호스팅 |
| 파일 저장 | 서버 로컬 | AWS S3 | 확장성 |
| 상태 관리 | 하드코딩 | 공통코드 테이블 | 유연성 |

## MVP 범위

### v1 포함
- 회원가입/로그인 (JWT)
- 게시글 CRUD
- 지역/카테고리 필터링
- 이미지 업로드 (S3)
- 좋아요

### v2: 인프라/품질
- Docker 컨테이너화
- GitHub Actions CI/CD
- 테스트 코드 보강
- 배포 환경 구축

### v3 이후
- 댓글, 북마크, 신고 (v3) - 검색은 게시글 목록 keyword 로 먼저 구현
- 태그, 대댓글, 팔로우, 알림 (v4)
- OAuth, 관리자 (v5)
